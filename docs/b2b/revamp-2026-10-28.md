## In one paragraph

The B2B Sales tab had no notion of who is logged in. Every list showed every
rep's records, and team membership was a hardcoded array (`B2B_ROSTER`,
`B2B_INBOUND_OWNERS`). Every Kylas inbound lead landed on one person. This
branch adds:

- an **identity layer**: who is on which team, and who is a manager, edited in
  the app by managers;
- a **round robin** that spreads inbound leads across the Inbound team;
- **per-person views** for Inbound and Outreach;
- a rebuilt **Outreach** tab, which now runs from the first meeting to the
  handover to KAM.

KAM is partly built: the Firm page and lens tiles. The Client Database got the
same lens tiles. Several Claude sessions did the work in one working tree, on a
shared base.

## Before you deploy: four prerequisites

> **PR #30 (2026-10-30)** adds two more, on top of the four below: deploy
> b2b-backend **PR #14** (`/b2b/waitlist`, `/b2b/studio-access`, no migration)
> and **PR #15** (`studio-staff-handoff`, migration 0022 `staff_handoff`, then
> `alembic upgrade head`). And every KAM needs their mobile on their Studio
> Space team record (console → Team), or the tab cannot sign them in.

1. **Deploy b2b-backend PR #13 (branch `b2b-crm-extra-and-team`) and run
   `alembic upgrade head`.** That runs two migrations. `0020_b2b_extra_and_team`
   adds the `extra` jsonb that stops the backend dropping CRM fields,
   `POST /rows/bulk`, and the team and assignment tables, which replaced
   `b2b-team.sql` (never applied, do not run it).
   `0021_b2b_admin_and_ec_visit` adds `b2b_team_member.is_admin` and the
   `b2b_ec_visit` table. **Neither has ever run against Postgres.** **Until
   they run, nothing breaks, but Invalid / Send to Outreach fields, requirement
   history and per-PI dates do not persist.** `/api/b2b/team` answers
   `tableMissing: true`, the Team tab says the tables are missing, and the round
   robin skips. Managers see every rep's records with an amber notice. Since
   2026-10-29 reps see only their own: Outreach matches them by BM phone or
   name, and Inbound shows them nothing until they are on the team. Without
   0021 alone, the B2B admin switch does not stick, and the EC visits card
   shows a 503 naming the migration.
2. **Check the Azure application settings** for `SUPABASE_SERVICE_ROLE_KEY` and
   `KYLAS_API_KEY`. The new routes read both server-side. The deploy workflow
   does not inject them, so a missing one passes `tsc` and the build, then
   throws `… is not set` in production (see root `CLAUDE.md`).
   `/api/b2b/waitlist` needs only `B2B_BACKEND_URL` / `B2B_BACKEND_SECRET`
   since 2026-10-29, plus b2b-backend's `GET /b2b/waitlist`.
3. **Pick the round-robin start time.** `INBOUND_ROTATION_START` in
   `lib/b2b/team/constants.ts` is `2026-10-29T00:00:00+05:30`. Leads created
   before it stay with whoever owns them.
4. **Watch the first real round robin.** The owner change is a JSON Patch on
   Kylas `/leads/{id}` `/ownerId`. It is verified by reading the owner back, but
   it has **never run against a real lead**: Kylas's API reference is not public.

## 1. Identity layer and the Team tab

**Problem:** `B2BSalesCRM` took no props, so no B2B view knew the user. Team
membership lived in two hardcoded lists that had already drifted apart.

**Change:**

- `tab-panels.tsx` passes `currentUser` into `B2BSalesCRM`.
- The shell loads the team once (`hooks/use-b2b-team.ts`, one request) and
  builds a `Viewer` (`viewerFor`).
- It passes `team` and `viewer` to each sub-tab that scopes (Inbound,
  Outreach).

| Piece | Path | Notes |
|---|---|---|
| Types, constants, pure rules | `lib/b2b/team/{types,constants,utils}.ts` | No `'use client'`, so route handlers import the same rules the UI uses (`canUseB2B`, `isB2BManager`, `rotationOrder`, `planRotation`) |
| Browser client | `lib/b2b/team/index.ts` | Bearer token + single-flight refresh on 401, the same as the store-checklist caller |
| Server only | `lib/server/b2b-team/{index,store,kylas}.ts` | Supabase service role + Kylas API key; never imported by client code |
| Routes | `app/api/b2b/team`, `app/api/b2b/inbound/assign` | Both start with `requireCaller` |
| Team tab | `components/b2b/views/team/` | Managers only |
| Schema | b2b-backend migration `0020_b2b_extra_and_team` (was `supabase/migrations/b2b-team.sql`, never applied) | `b2b_team_member`, `b2b_lead_assignment`; reached only by route handlers via `x-sync-key` |

Decisions worth knowing before changing any of this:

- **A member is keyed on the last 10 digits of their phone.** The phone is the
  one identifier the browser session, `requireCaller`'s `Caller` and
  `/user-organisation/` all share.
- **A member's Kylas user id is found by phone.** Kylas `GET /users` returns all
  185 users with phones and an `active` flag. A manager can override the match.
- **Manager** = role `superadmin`, `admin` or `b2b_manager`, **or** the new
  `b2b.manager` permission. Admins grant the permission under B2B Sales in the
  Admin permission checklist (`components/crm/admin/permissions.tsx`).
- **Team membership is a table, not a permission slug.** Managers, not only
  admins, must edit it, and each member needs a Kylas id stored somewhere.
- **`B2B_SALES_ROLES` moved** from `components/crm/constants.ts` to
  `lib/b2b/team/constants.ts`. The CRM constants are a `'use client'` module
  that imports Site Audit code, so a route handler cannot import it.

| Route | Who | What |
|---|---|---|
| `GET /api/b2b/team` | any B2B user | `{ members, tableMissing }` |
| `GET /api/b2b/team?kylasUsers=1` | manager | Kylas user list, for manual linking |
| `PUT /api/b2b/team` | manager | upsert one member; auto-links Kylas by phone and returns a `warning` if no match |
| `POST /api/b2b/inbound/assign` `{mode:'rotate', dryRun?}` | any B2B user | run the round robin; idempotent |
| `POST /api/b2b/inbound/assign` `{mode:'reassign', leadId, toPhone, reason}` | active inbound member or manager | move one lead and log it |

All of these were exercised against the Django stub:

| Request | Result |
|---|---|
| No token | 401 |
| Malformed token | 401 |
| Expired token | 401 |
| Caller not on the roster | 403 |
| Rep calling a manager action | 403 |
| Bad team, bad mode, or non-numeric lead id | 400 |
| Reassign by a non-member | 403 |

## 2. Inbound

**Problem:** every Presales-qualified lead goes to one Kylas user (Hardi,
`81181`): 245 of 245 over the two weeks before 2026-10-28, at 10–32 a day.
Fixing it inside Kylas was tried and failed.

**Change:**

- **Round robin.** It runs when anyone opens Inbound Leads, and on demand from
  the Team tab (Preview / Assign now).
  - **The pool** is: owner `81181`, the two inbound stages, created after the
    start time and within 7 days, with no `b2b_lead_assignment` row, and not
    already worked in the CRM.
  - **Rotation** is over active, in-rotation, Kylas-linked inbound members,
    sorted by name, continuing from the last assignee.
  - **The race guard** is a partial unique index on `lead_id` where
    `kind = 'round_robin'`. The claim row is written before the Kylas PATCH and
    deleted if Kylas refuses, so a failed lead is retried next run. At most 25
    leads per run.
- **Mine / All inbound.** A Kylas-linked rep defaults to "Mine", which is the
  `ownerId` passed to the fetch, not a UI filter. "All inbound" is one click
  away on purpose: reps cover for absent colleagues.
- **Reassign.** A new Owner card in the lead drawer. The route refuses leads
  outside the inbound pipeline and logs `kind = 'reassign'` with a reason.
- **Owner names come from the team table.** `B2B_INBOUND_OWNERS` is now only a
  fallback. The board shows the old six **plus** every member, so nobody's
  leads vanish before managers add everyone. Delete the constant once the Team
  tab is complete.
- **Bug fixed:** a logged call recorded `by: draft.owner` (the lead's owner),
  not the caller. With reassignment that credits calls to the wrong rep, so it
  now records the logged-in user. See `landmines.md`, "A logged call recorded
  the lead's owner as the caller".

Changed: `views/inbound/index.tsx`, `views/inbound/ui/daily-panel.tsx` (since
replaced by `ui/filters.tsx`, see `inbound.md` §One tab, three tile groups),
`drawers/inbound/index.tsx`, new `drawers/inbound/cards/owner.tsx`, and
`lib/b2b/data/reads.ts` (`fetchInboundBoard` takes an `ownerIds` set).
Requests on opening Inbound: 2, unchanged, plus 1 for the round robin once it
has members. The team list is one request at the shell.

**2026-10-29 (`9030ca0`): three tabs, Invalid, Send to Outreach.** The page
opens on **Clients** (open leads with no PI), **PI** (every lead that has had a
PI, date-ranged with a 30-day default, by PI-shared date or last call) and
**Results** (Closed, Lost, Invalid, sent to Outreach). **Invalid** is a status,
gated on a logged call, a reason and a 15-character note. Old `Enquiry invalid`
Lost rows read as Invalid, so the Lost count drops. **Office location** is a new
Client field. **Send to Outreach** is a checklist in the drawer that writes
`meta_data.outreach_referral`. New `meta_data` keys: `invalid_reason`,
`invalid_note`, `pi_shared_at`, `office_location`, `outreach_referral`. They
must survive the PR #27 backend's `b2b_crm` router too. **They did not**: it
dropped every key without a column, so these never persisted. Fixed by
backend migration 0020's `extra` jsonb (below).

**2026-10-29 evening (`07a5ff1` merge, `8337304`, then the sandbox commit).**
`origin/main` merged in, and its relay gate changed to `canUseB2B`. The three
tabs collapsed into one (Call today / Pipeline / Outcomes). Leads after 5 pm
count for the next working day. RNR is one click with an automatic
next-working-day follow-up. The Connected call form is the only follow-up
input. Attempts are uncapped. Calls and notes are CRM-only, credited to the
session user. Ready to close gates the no-response Lost reasons. Client details
gained primary and additional people and City. Send to Outreach asks for a
meeting location and a summary, and the Outreach row inherits the calls and
notes. The KAM handoff is gone from Inbound. Enq IDs are picked from deal
tickets, and four SPoCs show on each lead. The team store moved to the
b2b-backend. Detail in `inbound.md`; local testing in `sandbox.md`. Opening a
drawer costs one extra read (the client's second number's deal tickets) at
most; the Outreach row comes from the cached all-rows read.

## 3. Outreach

Built by a separate session; the full record is in `outreach.md` §The
2026-10-28 rebuild. In short:

- **No new table.** Everything lives in the outreach row's `meta_data`. New
  keys: `bm_phone`, `source`, `intake`, `handover`, `journey`,
  `whatsapp_group_link`, `converted_at`, `new_onboarding`, `pin` per meeting,
  and a few firm fields.
- **Scope** (`views/outreach/hooks/use-outreach-scope.ts`):
  - a manager sees every BM, plus a Team view;
  - a BM sees their own leads, by `bm_phone`, falling back to a whole-word name
    match for old rows;
  - a KAM sees only handovers addressed to them.

  Without the team table, everyone sees everything under an amber notice.
- **Lead sources:**
  - **From Inbound pool:** since 2026-10-29, only leads an Inbound rep **sent**
    with Send to Outreach (before that, every worked inbound lead). A manager
    assigns them, and the BM accepts or rejects with a reason. That acceptance is Inbound's
    "sign-off".
  - **CSV/Excel import:** previewed, 500 rows per file. Removed 2026-10-29, with
    Outreach's export (`outreach.md` §What a BM must capture).
  - **Manual add.**
- **The journey log is derived from a before/after diff on every write**
  (`withJourney`), so no write path can forget to log.
- **Action needed:** leads with an overdue or due-today reminder, most urgent
  first. It is one of the clickable tiles that replaced the nine tabs (see
  below).
- **Converted = first order**, and only an Enq-ID-fetched order counts.
  "New onboarding" means no order on that mobile in the previous 183 days.
- **KAM handover:** hard-gated on a WhatsApp group link and the sheet's payload.
  The 48h KAM sign-off is tracked and shown overdue, never auto-escalated.
- **Meeting notes are a hard gate on a held meeting; the live pin is not.**
- **Studio Space waitlist** (`app/api/b2b/waitlist`) reads b2b-backend
  `GET /b2b/waitlist` directly since 2026-10-29 (`outreach.md` §Studio Space
  waitlist). Until that route deploys the KPI reads Unknown, never zero.
- **Scorecard** of the sheet's eight KPIs (`models/outreach/kpis.ts`) for any
  period, per BM or as a team. Each KPI returns the leads behind it, so every
  tile opens its own list, with the uncounted leads and the reason they were
  not counted.
- **UI pass, same day:** the page became clickable tiles over one paged
  table, replacing nine tabs and an always-open filter bar. Its BM picker now
  lists the BMs who hold leads; before, it listed the stale roster. See
  `outreach.md` §The page is tiles you click.

Structure: `components/b2b/models/outreach.ts` became
`models/outreach/{index,handover,intake,reminders,kpis}.ts`. The views split
into `views/outreach/{hooks,intake,lenses,lists,performance}/`. New drawer
cards: `handover.tsx`, `journey.tsx` (`meetings.tsx` removed). Also
`lib/b2b/outreach/`, and `upsertOutreachLeads` in `lib/b2b/data/writes.ts`.

## Known gaps and follow-ups

- `components/b2b/views/inbound/index.tsx` was at 493 lines. The tile and lens
  rework later the same day brought it to 427, by moving the filters into one
  object and the board into `ui/board.tsx`.
- **Scoping is client-side.** Kylas and `b2b_lead` are read with keys the browser
  holds, so it is a focus aid, not confidentiality. The user chose this for
  Outreach and KAM.
- **The Kylas API key is hardcoded in `lib/api/core/kylas-client.ts`** in a
  public repo. That predates this branch, but this branch relies on the same
  key being able to reassign leads. Worth rotating, and moving behind a route.
- **KAM lists still read `B2B_ROSTER`.** The Leadership Board and Targets no longer do (`leadership.md`).
- **Outreach's handover target list** uses the old roster until the team table
  has KAM members.
- **The Leads tab drawer's writes skip Outreach's journey log.**
- **Dead-lead automation, the CRM-adherence function and KPI strips for Inbound**
  are designed (`sales-tab-redesign.md` §Inbound) but not built.
